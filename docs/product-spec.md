# PathLab AI 产品规格 v0.1（阶段 0）

日期：2026-10-17。状态：规格与可执行契约基线，不是已完成应用；待用户审阅。
依据：仓库总控提示词、用户明确提供的 Git/Prompt 留证要求。赛事入口、截止日期和评分数值本轮未复核，不作为已确认事实。

## 产品与范围

面向会背 BFS/A* 定义、但无法解释下一步选择的初学者。以校园配送任务形成“预测 → 执行 → 证据 → 诊断 → 改变条件 → 复盘”的学习闭环，不以动画数量或聊天框作为产品价值。

MVP：四个固定关卡；单位步长四邻域 BFS/A*；预测、单步/播放/暂停/重放/速度；节点检查器与事件时间线；封路/移动终点/重置；本地规则诊断；可选远程解释；本地进度及 JSON 导入导出；桌面和约 390px 移动端。

不做：登录、数据库、排行榜、Three.js、摄像头/眼动、语音、动态避障、随机/AI 地图、加权地形、十几种算法。阶段 0 不实现上述 MVP 功能，仅固化规格、数据与检查。

## 第一性原理纠偏

1. BFS 预测的是“下一次出队的节点”，不一定是“下一层节点”；同层遵守 FIFO。
2. A* 比较同一地图的最少步数与搜索范围；不承诺所有地图都比 BFS 扩展更少，不把路径步数叫耗时。
3. 封路发生在完整原始运行后；旧运行只读保留用于比较，但不适用于新 gridRevision。不是实时避障。
4. 先提交再揭示：预测候选可显示推理需要的层级/优先级，不给实际选择标记；用户能按规则推导答案是教学目的。
5. 误选一次只能描述观察，不能断言心理原因。没有判定依据时输出证据不足。
6. 四个关卡数据中的可达性、最短长度、预测点是否触发，必须等算法实现后通过实测确认；此阶段仅验证数据结构与边界。

## 可度量概念

- pathLength：路径边数；起终点相同为 0；不可达为 null，不能混同。
- discoveredCount：首次发现的唯一节点数（含起点）。
- selectionCount：有效选中/出队节点次数，包含被选中的终点，不计 A* 过期堆条目。
- expandedCount：实际检查其邻居的唯一节点数；终点选中即结束，不扩展终点。
- frontierPeak：有效待处理唯一节点集合的峰值，不以堆里过期条目计数。
- 预测准确率：首次提交正确数 / 实际提交的预测点数；分母 0 显示“尚无预测”，不显示 100%。练习重试另计。
- 提示级别、重试次数、反事实前后差异均来自实际事件；不测量注意力/能力。

## 完成与边界

完整应用须通过 acceptance.md 的 MVP 验收、真实用户操作、至少三条真实核心迭代链及发布材料审查。阶段检查通过不等于这些条件成立。
反馈说明必须清楚区分“本地规则诊断”“远程 AI 反馈”“远程失败已回退”；缺 API 不妨碍核心学习。
