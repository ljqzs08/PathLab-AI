# PathLab 教学内容与证据备稿

版本：2026-10-17 / 阶段 2（BFS）。这是围绕实际地图和已验证内核编写的内容，不是已上线的预测/提示/诊断界面，也不是用户学习效果报告。开发者答案与核验指标不得在预测提交前发送给学习页面或远程模型。

## 1. 内容原则

- 一个问题只考查一个核心选择规则，再让学习者引用可见事实解释，不用术语密度替代理解。
- “选中”指队首出队；“发现”指首次入队；“扩展”指实际检查邻居。终点被选中后不扩展，已发现数可以大于已选中数。
- pathLength 是路径边数，不是路径节点数、搜索节点数、动画时长或计算耗时。无路为 null，起终点相同为 0。
- BFS 的 h 固定为 0，不是节点到终点的真实距离，也不参与选择；同层节点仍按 FIFO 处理，不按离终点远近选。
- path_updated(final=false) 是从起点回溯到当前搜索节点的前缀，不表示配送机器人已经沿这些格子行走。
- 一次误选只是一次行为观察，不能直接给“只看终点距离”“不懂算法”等心理/能力标签。缺少证据就明确说不足。
- 完成标准是尝试预测、运行、改变条件并给出证据解释，不要求首次全对，也不能把预测正确直接当作掌握证明。

## 2. 四关内容卡

### L01：一层一层抵达

**开场提问（可在未来预测前使用，不附答案）**

> 每走一格的代价相同。请观察当前待处理节点的入队顺序：下一次会出队哪一个？你的依据是队列位置，还是到终点的远近？

**需要分清**：下一次出队不一定意味着进入下一层；FIFO 对同一层的先后顺序也有效。

**提交后的教师解释（已由 BFS 证据核验）**

原图第 2 次有效选择之前，快照 step=10，候选依次为 (0,1)、(1,2)、(0,3)，三者 g=f=1、h=0，entrySequence 分别为 1、2、3。下一次选择 step=11 的 (0,1)。尽管 (1,2) 更接近终点，BFS 仍先处理较早入队的节点。

对应机器位置：evidence/stage-2-bfs.json → missions[0].baseline.checkpoints[0]。这是算法事实，不是一次用户预测记录。

**复盘追问**：如果将终点从 (6,2) 移到 (6,4)，你预计路径步数和搜索节点数都会按同一比例变化吗？运行后分别核对。

**教师核验**：最短步数 6 → 8；expandedCount 22 → 30。这里只描述本图，不推广为固定比例。

### L02：施工区绕行

**开场提问**

> 围挡阻断直线路径。先区分两个问题：最短路线需要多少步？搜索为了找到它检查了多少节点？哪个指标回答了哪个问题？

**当前可讲**：BFS 的发现/选中/扩展口径与封路实验。

**已核验的算法对照**：同图 A* 与 BFS 最短步数均为 14；原图扩展 BFS 53、A* 27；封路后均为 16 步，扩展 BFS 52、A* 32。只描述本图的节点数，不声称所有地图 A* 必然搜索更少，也不据此推断耗时。

**提交后的教师解释**

原图最短步数为 14，扩展 53 个节点；封锁 (4,5) 后最短步数为 16，扩展 52 个节点。该实验同时改变了可通行节点和终点被选中的时刻。路线更长并没有让本次扩展节点数更多；这不是“封路让算法更快”的结论，因为没有测量耗时，也不是一般规律。

**复盘追问**：请分别引用 pathLength 和 expandedCount，写出两句话，不能把其中一个用作另一个的单位。

### L03：封锁东门，重新规划

**开场提问**

> 在原始调度完成后封锁 (4,2)。旧路径还能作为新地图的答案吗？请先找出旧路径中哪个条件已不成立。

**当前核验范围**：该关的 A* 已独立实现；BFS 只作最短距离对照。两者步数均为原图 8、封路后 12；A* 扩展数为 8 → 16，BFS 为 23 → 26。各自事件轨迹分开，不把 BFS 的选择轨迹冒充 A*。

**教师核验**：原 BFS 路径经过 (4,2)，最短 8 步；封锁后新路径不经过该格，最短 12 步。上下绕行均可达到该最短距离；本轮固定上右下左的 BFS 选择了上方绕行。

**复盘追问**：用“修改坐标 → 旧路径中的失效位置 → 新路径及步数差异”三段说明。不要只说“AI 重新算了一次”。

**必须避免的误导**：这是两个静态地图版本的离散规划，不是机器人运行中实时避障。未来需要新 runId/gridRevision 并保留旧记录；此会话编排尚未实现。

### L04：调度员复盘

**开场提问**

> 自主选择一个已经实现的算法规则。预测下一次选中节点，然后用一条可见事件说明原因。改变终点后，哪些旧结论仍成立，哪些需要重新计算？

**当前教师核验**：BFS 原图最短 14 步、扩展 45 个节点；终点改到 (8,0) 后最短 8 步、扩展 25 个节点。两次运行的地图终点条件不同，不作为同输入的算法效率对照。

**未来复盘记录模板（不是已经收集到的回答）**

- 我改变的条件：____。
- 原运行的可见证据 ID 与事实：____。
- 新运行的可见证据 ID 与事实：____。
- 因此我能支持的结论：____。
- 这些证据还不能支持的结论：____。

真实学习事件 ID 由后续编排层产生；不能把本轮脚本的 step 或合成 schema-fixture ID 当作用户会话证据。

## 3. 提示与反馈措辞备稿（尚未接入 UI）

| 时机 | 可用措辞 | 边界 |
|---|---|---|
| 预测前，无提示 | 请根据当前队列或算法优先级选择，先提交再揭示。 | 不标记实际下一节点，不发送完整后续轨迹 |
| 第一级 | 本关每步代价相同。BFS 使用什么顺序取出节点？ | 只提醒规则 |
| 第二级 | 比较已经可见的候选入队序号，先区分“发现”和“选中”。 | 不替用户点击 |
| 第三级 | 先找最早入队且尚未出队的候选，再说明依据。 | 不引入 BFS 不使用的启发式值 |
| 提交后 | 本次实际选中 X，来自可见的队列顺序。你的选择为 Y。 | X/Y 必须由实际事件填充，不使用示例冒充 |
| 证据不足 | 这一次选择不足以判断原因。你能说明使用了哪条规则吗？ | 不推断能力或心理状态 |
| 反事实后 | 你改动了 C；旧路径含/不含该条件。请对照两次有效运行。 | 必须引用真实 run/可见事件，不复用过期答案 |

提示升级必须由用户请求；默认不因为答错自动给最高级答案。远程解释只在提交/揭示后按契约允许的事实请求；当前无远程服务。

## 4. 可复用内容验收

1. 每条数值可在 evidence/stage-2-bfs.json 中定位，并由 inspect:bfs 重新产生。
2. 默认八次 BFS 运行的第 2、4 次选中前都至少有两个候选；这是静态轨迹可用性，不等于交互门控验收。
3. 未来 UI 接入时，自动检查 DOM、辅助技术、时间线、Canvas 和网络请求都不提前泄露答案；目前没有这些功能，不提前打勾。
4. 真实试用后只记录实际选择、反馈和复盘，不虚构“准确率提升”“教学有效”或用户人数。
5. 后续 A* 必须独立测量，再补算法比较内容；不可从 BFS 结果推算其扩展节点数或 checkpoint 位置。
