# 项目详情：让“下一步”值得思考
## 不是播放答案，而是建立可检验的解释
常见路径动画容易让人看到终点，却未必理解队列为什么选择某个节点。PathLab AI 把观看过程改成学习者可参与的决策：先从已揭示的前沿预测下一步，提交后看真实结果，再保持算法不变修改一个条件，用实际事件解释差异。
| 项目项 | 当前实现 |
| --- | --- |
| 定位与用户 | 面向 BFS / A* 初学者，可用于自学、课堂演示与算法实验；不是通用聊天平台。 |
| 学习目标 | 区分路径步数、扩展节点、前沿与启发式；形成“预测—验证—解释”的习惯。目标不是已证明的教学效果。 |
| 交付形态 | Next 工程版 + 可单独复制运行的完整离线 HTML；两者共享算法、组件与关卡数据。 |
| 核心循环 | 读任务 → 先预测 → 显式提交 → 回放搜索 → 单因素实验 → 引用事件生成报告。 |
## 四个任务的递进关系
| 任务 | 学习侧重 | 算法 |
| --- | --- | --- |
| L01 一层一层抵达 | 观察 FIFO 队列与逐层扩展 | BFS |
| L02 施工区绕行 | 在障碍中理解候选与绕路 | BFS / A* |
| L03 封锁东门，重新规划 | 条件变化后重新运行，不复用旧答案 | A* |
| L04 调度员复盘 | 结合对照结果与事件组织解释 | BFS / A* |
来源：产品规格、关卡数据、README 与学习会话源码。七项材料要求与页码见第 14 页。

# 使用方式：先打开，再完成一轮
## 推荐体验：完整离线 HTML
1. 在 Edge 中打开仓库内的 PathLab-AI/PathLab AI.html。无需安装 Node.js、启动 localhost、填写 API Key 或保持联网，即可体验本地核心学习。
2. 从左侧选择关卡，读任务说明；点击“开始预测”。遇到检查点时选地图候选或候选卡，点击“提交预测”后查看实际选择。
3. 用单步或播放检查搜索。结束后查看真实路径与计数；进入条件实验，再做一次相同算法的运行，最后引用事件写解释并生成报告。
:::image 03-search-result 264
## 工程版与数据迁移
需要源码运行时，先安装仓库规定的 Node.js 环境，在根目录依次使用 scripts/Invoke-ProjectNpm.ps1 执行 ci 和 run dev；浏览器打开本机 3000 端口。完整可复制命令、环境模板与生产模式见 README 和技术文档第 18 页；核心功能不依赖远程 AI。
更换浏览器、移动 HTML 或切换工程版前先导出 JSON，到目标版本预览并确认导入；不要假定本机存档会自动跟随文件。
来源：README、package.json、存储规格；图 03 为本轮实际离线运行，路径步数 6、扩展节点 22。

# 关键体验一：先作判断，后看答案
:::image 02-prediction 370
## 点击不是答案揭示的捷径
地图候选与候选卡同步选中，必须再显式提交；页面不能直接读取私有会话中的未来轨迹。学习者可以依据已经出现的前沿、父节点和成本作出判断，而不是从预先展示的最终路径倒推答案。
## 可以怎样使用
自学时先说出“我为什么选它”，再查看结果；演示时暂停在检查点，让观众比较候选。预测偏差只记录该次选择，不给学习者贴能力标签，也不把几次符合规则的选择等同于已经掌握算法。
来源：LearningSession、LearningWorkbench、GridCanvas 与门控验证；截图为 AI 演示选择，非真实学生实验。

# 关键体验二：一次只改一个条件
:::image 04-condition-comparison 160
## 一个真实例子：绕得更远，也扩展得更多
本轮在 L01 保持 BFS 不变，应用关卡允许的单一条件修改后重新预测与搜索。路径步数从 6 变为 8，扩展节点从 22 变为 30。界面保留两次运行与修订关系，支持解释“条件改变后发生了什么”，而不是承诺修改一定更优。
## 解释必须带来源
在复盘中勾选本次已揭示事件，输入自己的解释，生成保留引用的本地报告。报告检查记录与引用是否齐备，不自动判定自由文本解释正确，也不判定学习者已经掌握。
:::image 06-evidence-report 195
来源：本轮截图清单与 ReflectionPanel / report 领域逻辑；图中的解释显式标为 AI 自动演示，不当作学生原话。

# 自由玩法：把地图变成自己的问题
:::image 07-playground 278
## 独立的 9×7 实验区
支持画障碍、擦除、移动起终点、撤销、空白 / 绕路 / 岔路预设。先预测哪个算法扩展更少，再同时运行 BFS 与 A*，查看真实计数；选择算法和速度回放节点选择过程，完成后显示最终路径。
| 本轮截图中的结果 | BFS | A* |
| --- | --- | --- |
| 最短路径步数 | 14 | 14 |
| 扩展节点 / 前沿峰值 | 39 / 6 | 14 / 5 |
## 推荐小挑战
同一路径步数能否有不同扩展量？增加一个障碍是否一定更难？先写预测，只改一次地图，再看真实计数。上表只是这张地图的一次演示，不能推广为“A* 在所有地图总更快”。
自由区不改变四关成绩、不写入本机学习存档，也不向远程 AI 提供地图或学习事实；刷新页面后不保留编辑。
来源：Playground、playground-spec 与本轮图 07 清单。扩展数量是搜索计数，不是耗时基准。

# 项目亮点：可玩，但不牺牲可解释性
| 亮点 | 已落地的设计与价值 |
| --- | --- |
| 预测式参与 | 地图和候选卡双入口，显式提交后才揭示；让交互围绕算法判断，而不是无意义点击。 |
| 可重复的搜索 | 固定邻居顺序与 A* 平局规则，同一输入产生可复查的事件轨迹；解释能够落到具体节点和事件。 |
| 单因素对照 | 保留上次结果，改变允许的单个条件，再以相同算法重跑；把“我觉得”变为有范围的事实比较。 |
| 独立沙盒玩法 | 自由编辑、先猜后比、双算法回放与撤销，增加探索空间，同时不污染正式关卡和学习记录。 |
| 双形态交付 | 完整 HTML 不是跳转页或截图；脱离开发服务仍可运行核心学习，降低评审与演示的启动门槛。 |
| 证据与 AI 分权 | 本地算法决定真值，AI 只能辅助组织与解释已有事实；无密钥也能完成学习闭环。 |
| 恢复与包容性 | JSON 预览确认、版本校验、键盘与等价 DOM、移动布局和减少动态偏好共同覆盖操作体验。 |
## 视觉与动效服务于理解
深色网格、节点状态、候选反馈与路径颜色帮助识别搜索进展；有限入场和按压动效提示状态变化，遵循 reduced-motion，不以持续装饰动画争夺注意力。
> 亮点是已有实现的组合设计，不作“首创”“零缺陷”“一定提升学习成绩”或全设备绝对流畅的承诺。
来源：架构、动效、存档、自由地图与网页复盘规格及相应验证记录。

# AI 测试技术：落到检查与修复闭环
## 落地方式，而非给测试贴一个 AI 标签
AI 参与设计测试、操作工具、读取实际失败并修改代码；TypeScript、Node test、Playwright 与 axe 仍是确定性检查工具，不等于每条断言都由大模型主观判断。应用运行时也不依赖模型判定算法正确或测试通过。
| 检查层 | 实际落地 | 证明的范围 |
| --- | --- | --- |
| 静态约束 | TypeScript 类型检查、ESLint 零警告规则、生产构建 | 接口与工程可构建性；不代替运行验证 |
| 领域测试 | 独立算法 oracle、确定性、事件 / 引用 / 存档边界、AI 响应模拟 | 指定输入与边界行为，不是教学效果评估 |
| 浏览器测试 | Edge + Playwright；四视口、键盘、Canvas / DOM、复制回退及 axe 规则检查 | AI 自动化可复查的浏览器行为，非人工或手机真机验收 |
| 复现核验 | 干净源码检出、新 npm 缓存、安装至 L01 闭环计时与 HTML 哈希 | 该机器与明确计时范围，不保证任意环境十分钟 |

# 关键技术：确定性内核与受控边界
:::architecture
| 技术 | 在项目中的用途 |
| --- | --- |
| Next.js / React / TypeScript | App Router 工程版与共享组件；完整 HTML 从同一实现生成，不维护第二套算法。 |
| BFS / A* / 二叉最小堆 | BFS 用 FIFO 头索引；A* 按 f、h、入队次序解平局，邻居顺序固定为上右下左。 |
| 私有会话与只读投影 | 完整轨迹留在私有字段，UI 只获取已揭示视图；Canvas 与等价 DOM 消费同一投影。 |
| JSON Schema 与语义校验 | Ajv 检查结构，领域层检查事件引用、运行和修订一致；存档通过版本化命令重放恢复。 |
| 外围 AI 适配 | 仅消费已揭示事实；API 密钥只在服务器，默认关闭，超时或失败保留本地反馈。 |
## 架构取舍
采用分层单体而非微服务；算法、学习编排、视图与外围适配分离。单位代价四邻域和地图规模有明确上限，不把快照记录成本包装为所有输入都线性，也不将共享口令当作公开生产级账号体系。
来源：architecture、contracts、算法、session、progress 与 deepseek 源码。图为概念依赖 / 数据边界，不是精确 import 图。
