## 我已经替你修正了原方案中的 5 个风险

### 1. 修正“最短路径”和“最快路径”的混用

如果第一版只是普通无权网格，准确说法应该是：

- 最少步数；
- 搜索节点数；
- 搜索步骤；
- 算法运行效率。

不要直接说“最快路径”。

只有加入带权地形，并且实现 Dijkstra 或带权 A* 后，才能讨论“最低通行代价”。

### 2. 删除无法证明的“视线方向”

原方案中提到记录“用户选择时的视线方向”，但没有眼动设备或摄像头数据时，这个说法不成立。

我已经改成只记录真实可验证行为：

- 用户选择了哪个节点；
- 选择耗时；
- 重试次数；
- 使用了哪一级提示；
- 用户预测与算法结果是否一致；
- 用户是否重复出现某类错误。

### 3. AI 不负责计算算法结果

算法结果必须由确定性程序产生：

```text
地图数据
→ BFS/A* 算法
→ 搜索事件日志
→ Canvas 与指标面板
```

AI 只负责：

```text
读取结构化事件
→ 识别学习错误
→ 生成分层提示
→ 推荐下一次练习
```

这样可以避免 AI 和算法动画不一致。

### 4. 远程 AI 与本地诊断双模式

作品不能因为没有 API Key 就无法演示。

因此完整提示词要求：

- 有 API 时：使用真实远程 AI 增强反馈；
- 没有 API 时：使用本地规则诊断；
- UI 必须明确显示“远程 AI 增强”或“本地规则诊断”；
- 不能把本地规则伪装成远程大模型。

### 5. 把一次性开发改成真实演进链

完整方案要求至少保留：

- 算法引擎 Prompt 链；
