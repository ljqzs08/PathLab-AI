重新优化后的方案：PathLab AI
我重新对照了赛事方向、评分重点、成熟交互教育作品和你已有的个人网站/H5 游戏能力后，结论是：
PathLab 不能再只是“BFS 和 A 动画演示器”。*
它应该升级为一个以真实场景为载体、以用户决策为核心、以 AI 诊断与陪练为增强的“可解释路径决策学习实验室”。

这是关键调整。因为现有优秀作品已经覆盖了算法动画、代码执行可视化、用户输入和逐步回放等能力，例如 VisuAlgo 提供图遍历的交互式输入和动画，Algorithm Visualizer 也已经形成了从代码到算法可视化的平台。(visualgo.net)
如果我们只做“地图 + 小方块 + BFS/A* + 播放按钮”，功能可能完成，但原创性和参赛竞争力不够。
一、产品重新定位
产品名称
PathLab AI
可解释路径决策学习实验室
一句话定位
通过真实场景模拟、用户决策预测、算法过程可视化、反事实实验和 AI 个性化陪练，帮助初学者理解“算法为什么做出这个路径决策”。

不再强调
- “我能展示 BFS”
- “我能展示 A*”
- “我有一个 Canvas 动画”
- “我接入了 AI 聊天”
改为强调
- 用户能否预测算法下一步；
- 用户能否解释算法为什么选择某个节点；
- 用户修改地图后，能否理解结果为什么变化；
- AI 能否识别用户的错误思维；
- 系统能否让用户从“看动画”转向“做决策”。
二、重新选择产品场景：不要再做普通迷宫
普通迷宫太像教学 Demo，也容易与现有算法可视化网站雷同。
我建议将场景改成：
「校园智能配送与应急路径实验室」
用户扮演校园调度员，为机器人规划路线。
地图中包括：
- 教学楼；
- 宿舍；
- 食堂；
- 医务室；
- 图书馆；
- 施工区域；
- 临时封锁区域；
- 人流拥堵区域；
- 需要优先送达的目标点。
这样，算法不再是脱离场景的方格移动，而是：
在有限条件下，如何为机器人选择一条合理、快速、可解释的路线。

这个场景有几个好处：
1. 有真实的问题背景；
2. 方便解释“最短路径”和“最快路径”的区别；
3. 可以自然引出障碍、代价、动态变化；
4. 便于构建关卡和演示故事；
5. 仍然可以用 Canvas 实现，不会把项目做成大型游戏。
但要注意：场景只是教学包装，核心算法必须保持准确。
三、产品核心学习闭环
PathLab 的核心不应该是“观看”，而应该是以下六步：
提出任务
  ↓
用户预测
  ↓
拖拽实验
  ↓
算法执行
  ↓
AI解释
  ↓
反事实复盘
1. 提出任务
例如：
“机器人需要从图书馆前往医务室。施工区不可通行，请选择你认为最合理的下一步。”

系统给出：
- 地图；
- 起点；
- 终点；
- 障碍；
- 当前算法；
- 本关学习目标。
2. 用户预测
算法运行到关键节点后暂停：
“你认为接下来应该扩展哪个节点？”

用户点击某个候选节点。
系统记录：
- 用户选择；
- 算法实际选择；
- 用户选择时的视线方向；
- 是否忽略了已走距离；
- 是否只关注了终点距离；
- 是否误解了优先队列顺序。
3. 拖拽实验
用户可以直接改变条件：
- 拖动终点；
- 添加障碍；
- 删除障碍；
- 移动封锁区域；
- 调整拥堵代价；
- 更换算法；
- 改变播放速度。
Observable 的优秀之处在于把滑块、按钮、选择框等输入与可视化结果联动，让用户通过改变参数理解数据变化。PathLab 应该借鉴这种“操作即实验”的逻辑，而不是把控件当作装饰。(observablehq.github.io)
4. 算法执行
算法执行不是单一动画，而是可观察的事件流：
- 当前节点；
- 候选节点；
- 已访问节点；
- 被淘汰节点；
- 当前最优路径；
- 估算代价；
- 最终路径。
5. AI解释
AI根据用户刚刚的行为生成反馈：
“你选择了距离终点最近的节点，但没有考虑已经走过的距离。A* 的判断不是只看离终点多远，而是综合考虑已付出的代价和剩余估计代价。”

6. 反事实复盘
系统继续追问：
“如果把左侧道路封锁，A* 是否还会选择同一个节点？”

用户重新实验，观察：
- 哪些节点的优先级变化；
- 搜索范围如何变化；
- 路径是否变长；
- BFS 与 A* 的差异是否仍然存在。
这一步是 PathLab 与普通算法演示器真正拉开差距的地方。
四、参考优秀作品，但不复制作品
我建议借鉴的是交互教育方法，而不是页面、代码、图形和文案。
1. 借鉴 TensorFlow Playground：直接操控，而不是先写代码
TensorFlow Playground 允许用户通过控件调整数据集、网络结构和训练参数，直接观察模型变化，不要求用户先写完整代码。(playground.tensorflow.org)
PathLab 可以借鉴：
- 用户直接修改地图；
- 用户直接调整参数；
- 用户立即看到结果；
- 每个控制项都必须对应一个可解释变化。
但不能复制它的：
- 页面布局；
- 颜色系统；
- 网络节点表现方式；
- 文案；
- 源代码。
2. 借鉴 Distill：把解释融入过程
Distill 强调动态、清晰、可交互的科学解释，使用响应式图示让读者通过操作形成直觉，而不是先读一整篇理论文章。(distill.pub)
PathLab 可以采用：
- “先操作，再解释”；
- 每次只讲一个概念；
- 解释文字跟随当前步骤变化；
- 让动画、数值和语言描述指向同一个状态。
3. 借鉴 Observable：建立参数—结果联动
Observable 的输入控件可以和图表、数据表、计算结果联动，适合探索式学习。(observablehq.github.io)
PathLab 可以把：
- 播放速度；
- 障碍数量；
- 起点终点；
- 当前算法；
- 启发式权重；
都连接到：
- 搜索范围；
- 路径长度；
- 节点数量；
- 运行步骤；
- AI反馈。
4. 借鉴 VisuAlgo 和 Algorithm Visualizer：逐步、可回放、可检查
VisuAlgo 支持图输入、算法运行和动画展示；Algorithm Visualizer 强调从代码执行过程到视觉状态的映射。(visualgo.net)
PathLab 不应该只展示“路线结果”，还要展示：
- 为什么访问这个节点；
- 当前候选节点如何排序；
- 哪些节点被排除；
- 每一步数据如何变化。
5. 借鉴 Nicky Case：让用户通过探索学习
Nicky Case 将互动解释设计成“通过玩来学习”，并强调互动内容不必完全线性，可以根据用户兴趣和已有知识调整探索路径。(blog.ncase.me)
PathLab 可以设计成：
- 新手先走引导任务；
- 熟悉算法后自由编辑地图；
- 用户可以选择“看解释”或“继续挑战”；
- 同一个知识点通过多个不同场景反复迁移。
五、PathLab 的原创核心
为了避免被评为“已有算法可视化的简单复刻”，我建议把原创性集中在五点。
原创点一：预测优先，而不是播放优先
普通算法可视化通常是：
点击播放 → 观看算法运行
PathLab 改成：
暂停 → 用户做判断 → 系统揭示真实结果 → AI诊断
这让用户成为决策参与者。
原创点二：AI识别“错误思维”，而不是只给解释
AI不只说“答案错误”，还要判断用户属于哪一类错误：
- 只看终点距离；
- 忽略已经走过的距离；
- 把 BFS 当成“直线优先”；
- 认为搜索范围越小路径就一定越短；
- 混淆访问节点和最终路径；
- 没有理解启发式函数的作用。
原创点三：反事实实验
用户可以改变一个条件，重新观察算法：
- 封锁一条道路；
- 移动终点；
- 增加拥堵；
- 改变算法；
- 改变启发式权重。
重点不是“再跑一次”，而是回答：
“哪个条件变化导致了哪个结果变化？”

原创点四：算法结果与学习反馈分离
算法结果由确定性程序生成，AI只解释结构化结果。
这样可以避免：
- AI计算错误；
- AI与动画不一致；
- 结果不可复现；
- 没有 API 就无法演示。
原创点五：形成学习证据
系统不只显示“完成关卡”，还记录：
- 用户第一次预测是否正确；
- 用户重试次数；
- 常见错误类型；
- BFS 和 A* 的理解差异；
- 关卡前后测试结果；
- 用户能否用自己的话解释算法。
这让作品从“可视化 Demo”升级为“学习工具”。
六、重新设计功能结构
首页：任务入口
不做普通的产品宣传页，而是直接呈现一个任务：
“校园东区道路封锁，机器人如何最快到达医务室？”

首页包括：
- 场景介绍；
- 学习目标；
- 当前进度；
- 开始实验按钮；
- 进入自由实验室按钮。
页面一：任务地图
核心区域：
- Canvas 地图；
- 起点；
- 终点；
- 障碍；
- 道路状态；
- 当前任务说明。
右侧或底部：
- 当前算法；
- 任务目标；
- 开始实验；
- 编辑地图；
- 重置地图。
页面二：算法驾驶舱
展示：
- 当前节点；
- 候选节点列表；
- 已访问节点数；
- 路径长度；
- 搜索步骤；
- 当前优先级计算。
A* 可以展示：
f(n) = g(n) + h(n)
但不能一开始就展示一堆数学公式。应该允许用户点击某个节点后再展开：
- g(n)：已经走过的代价；
- h(n)：到终点的估计代价；
- f(n)：综合优先级。
页面三：预测挑战
系统暂停后展示三个或四个候选节点。
用户选择后显示：
- 你的选择；
- 正确选择；
- 选择依据；
- 你的错误类型；
- 下一步提示。
页面四：算法对比
左右并列：
- BFS；
- A*。
底部显示：
- 最终路径长度；
- 搜索节点数；
- 搜索步骤；
- 是否找到最优路径；
- 两种算法的访问差异。
页面五：AI复盘报告
包括：
- 本次学习结果；
- 你做对的地方；
- 你反复出现的错误；
- 推荐再次挑战的关卡；
- 一条关键概念；
- 一个迁移问题。
七、算法路线需要重新分层
之前直接锁定 BFS + A* 可以作为 MVP，但完整产品需要更清楚的学习递进。
Level 1：BFS——什么是无权最短路径
地图规则：
- 上下左右移动；
- 每一步代价相同；
- 不考虑地形差异。
学习目标：
- BFS 一层一层扩展；
- 第一次到达终点时得到最短步数；
- 搜索顺序与“离起点的层数”有关。
Level 2：BFS vs A*——搜索范围有什么不同
学习目标：
- 两者可能得到相同的最短路径；
- A* 使用启发式信息；
- A* 通常能减少无关搜索；
- 搜索节点少不等于路径一定更短。
Level 3：Dijkstra vs A*——路径代价不再相同
地图加入：
- 普通道路；
- 草地；
- 拥堵区域；
- 高代价区域。
这时需要明确：
- BFS 不适合直接处理带权路径；
- Dijkstra 处理非负权重；
- A* 在合适启发式下寻找最优路径。
这一关理论价值较高，但可放在增强版，不应阻塞第一版提交。
Level 4：动态路径——条件发生变化时重新决策
例如：
- 某条路突然封锁；
- 机器人电量下降；
- 终点临时改变；
- 某区域变成高风险区域。
重点学习：
- 算法不是一次性算完后永远有效；
- 环境变化会导致重新规划；
- 规划结果要服从新的约束。
八、AI 功能必须具体化
AI 功能一：分层提示
不要一次直接告诉答案，设置四级提示：
一级提示：观察
“先观察当前候选节点距离起点有多远。”

二级提示：规则
“BFS 会优先处理更早进入队列的同层节点。”

三级提示：比较
“比较这两个候选节点的 g(n) 和 h(n)。”

四级提示：揭示
“正确节点是 D4，因为它的 f(n) 更小。”

这样可以体现教育价值，而不是让 AI 直接替用户完成思考。
AI 功能二：错误类型识别
通过用户事件日志识别：
错误类型：
- only_goal_distance
- ignore_path_cost
- confuse_visited_and_path
- misunderstand_queue_order
- overtrust_greedy_choice
AI 功能三：自动生成挑战
AI可以根据用户的错误生成新的任务描述，例如：
“你连续两次只关注离终点的距离。下一关会设置一条看似更近、但必须绕行的路线。”

但生成的地图必须经过程序校验：
- 起点终点合法；
- 至少存在一条路径；
- 难度符合范围；
- 最优解可计算；
- 不出现无法解释的结果。
AI 功能四：学习复盘
AI生成的报告必须引用真实数据：
“本次你完成了 4 次预测，其中 2 次只根据终点距离做判断。建议再次挑战‘施工区绕行’关卡。”

禁止生成无数据依据的夸奖，例如：
“你已经完全掌握了 A* 算法。”

九、技术架构重新优化
推荐技术栈
React
TypeScript
Canvas 2D
CSS Modules 或普通 CSS
LocalStorage
可选 AI API
我不建议第一版使用 Three.js。Three.js 更适合：
- 三维空间；
- 3D 神经网络；
- 具身机器人；
- 空间数据；
- 复杂模型关系。
PathLab 的核心是二维网格和学习交互，Canvas 2D 更轻、更容易稳定，也更符合你已有 H5 游戏能力。
核心数据流
用户操作
  ↓
Interaction Logger
  ↓
Deterministic Algorithm Engine
  ↓
Search Event Log
  ↓
Canvas Renderer
  ↓
Learning Diagnosis
  ↓
AI Feedback Adapter
关键原则
- React 不直接计算算法；
- Canvas 不保存学习状态；
- AI 不决定算法结果；
- 所有关键动作生成事件日志；
- 同一地图和参数必须得到同一结果；
- 无 AI 时仍可完成核心教学流程。
十、参赛评分对应关系
评分维度	PathLab 的具体证据
过程可复现性	固定关卡、固定随机种子、结构化事件日志、细粒度 Git、Prompt 记录
解题有效性	面向算法初学者解决“会背不会解释”的学习问题
方法创新性	预测—执行—诊断—反事实实验，而不是自动播放
工程质量	确定性算法内核与 AI 解释层分离，AI故障可降级
用户体验	地图拖拽、单步执行、速度控制、移动端适配、视觉反馈


这里最值得强调的是：
AI不是作品的标题装饰，而是用于诊断学习行为、生成分层提示和设计后续挑战。

十一、演示视频应该这样讲
按你提供的赛事页面要求，省赛作品提交截止日期为 2026年11月18日，所以演示不能做成“功能列表式录屏”，而要讲清楚一个完整案例。
推荐 6 分钟演示结构
0:00—0:40：提出问题
展示学生知道 BFS 和 A*，但不知道算法为什么选择某个节点。
0:40—1:30：进入校园配送任务
展示真实场景和学习目标。
1:30—2:20：用户第一次预测
用户做出一个看似合理但错误的选择。
2:20—3:10：算法逐步执行
展示 BFS 或 A* 的搜索过程和节点优先级。
3:10—4:00：AI诊断
AI识别用户“只看终点距离”的错误思维。
4:00—4:50：反事实实验
用户封锁道路，重新运行算法，观察搜索结果变化。
4:50—5:30：BFS 与 A* 对比
展示路径相同但搜索范围不同，或者在带权场景中展示算法差异。
5:30—6:30：AI协同开发证据
展示：
- 如何让 AI 生成算法模块；
- 如何要求 AI 保持算法正确性；
- 如何修复 Canvas 拖拽偏移；
- 如何通过测试验证结果；
- 如何保留 Prompt 和 Git 演进链。
十二、明确删除的功能
为了保证作品完整度，我建议暂时删除：
- 账号登录；
- 排行榜；
- 多人对战；
- 复杂社交；
- 3D 校园地图；
- 无限 AI 生成地图；
- 语音聊天；
- 同时支持十几种算法；
- AI 直接修改源代码；
- AI 直接给出算法答案；
- 复杂后台系统。
这些功能会让作品看起来更大，但不一定让评分更高。
最终优化后的立项结论
产品名称
PathLab AI：可解释路径决策学习实验室
产品类型
AI 驱动的高交互教育与可视化 H5 应用。
核心场景
校园智能配送与应急路径规划。
核心用户
算法初学者和高校计算机相关专业学生。
核心学习问题
帮助用户理解：
- BFS 如何逐层搜索；
- A* 如何综合已走距离和估计距离；
- 搜索节点数量与路径长度的区别；
- 地图条件变化后，为什么需要重新规划。
核心交互
用户预测
→ 算法执行
→ 视觉解释
→ AI诊断
→ 反事实实验
→ 学习复盘
首版范围
- BFS；
- A*；
- 无权网格；
- 4 个固定关卡；
- 地图拖拽；
- 障碍编辑；
- 单步与回放；
- 预测挑战；
- AI分层提示；
- 无 AI 降级模式；
- 移动端适配；
- 学习记录。
增强范围
- Dijkstra；
- 加权地形；
- 动态障碍；
- AI生成挑战；
- 学习报告；
- 前后测评。
最重要的原创性表达
PathLab AI 不是把算法画出来，而是让用户在算法运行中做判断，再由 AI 根据真实行为解释错误，并通过反事实实验帮助用户建立可迁移的算法直觉。

这版方案比之前的“寻路算法可视化实验室”更适合参赛：保留你的 H5 游戏和 Canvas 优势，同时补上真实场景、教育闭环、AI 作用、原创交互和可复现证据。
